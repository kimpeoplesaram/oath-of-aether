# 에테르의 서약 (The Oath of Aether)

타자 입력을 전투 조작 방식으로 사용하는 판타지 액션 RPG 프로토타입입니다.

## 현재 구현 범위 (5단계)

- 타이틀 화면 / 모험가 생성 (이름 + **6개 직업** 중 선택: 검사·성직자·마법사·궁수·도적·음유시인)
- **탑뷰 도트 그래픽 오버월드**: 방향키/WASD로 직접 맵을 돌아다니는 실제 캐릭터
  (코드로 그린 픽셀 캐릭터 스프라이트, 걷기 애니메이션 포함)
- 몬스터에게 다가가면 전투 진입, 전투 화면도 캐릭터/몬스터 스프라이트가
  마주보고 싸우는 비주얼로 변경
- 핵심 타자 입력 전투 (스킬 문구 입력 → 공격, 몬스터 예고 공격 → 회피 문구 입력)
- **캐릭터 성장**: 몬스터 처치 시 경험치 획득 → 레벨업(체력/공격력 상승, 완전 회복),
  장비(무기/방어구) 드랍 및 자동 장착, 체력은 오버월드 ↔ 전투 사이에 유지됨
- **퀘스트**: "숲 정찰(슬라임 2마리)" → "고블린 소탕(2마리)" 순서로 진행되는
  토벌 퀘스트, 오버월드 HUD에 진행도 표시, 완료 시 보너스 경험치
- **던전/보스**: 퀘스트를 모두 완료하면 오버월드에 던전 입구(포탈) **2곳**이
  열립니다. 체력 320의 "숲의 수호자"와 체력 380의 "얼음 망령" 중 원하는 보스에
  도전할 수 있으며, 승리 시 대량 경험치와 해당 직업 전용 최상급 장비(또는
  공용 방어구)를 확정 드랍합니다. 두 보스 모두 반복 도전이 가능합니다.
- **멀티플레이 + 협동 전투**: 서버 주소 + 방 코드만 공유하면 같은 오버월드에서
  서로를 보며 돌아다니다가, 같은 몬스터(보스 포함)에게 다가가면 **함께 전투**에
  들어갑니다. 몬스터 체력은 서버가 공유 관리하고, 전투가 끝나면 참가자 전원이
  경험치/퀘스트 진행을 동시에 받습니다. (최대 6인, `server/` 폴더의 Node WebSocket 서버)
- **직업별 협동 역할**:
  - 검사 = **탱커** — "도발" 사용 시 몬스터의 다음 공격을 자신에게 집중시키고,
    평소에도 몬스터가 검사를 더 자주 노립니다.
  - 성직자 = **힐러** — "치유의 빛"으로 파티에서 가장 많이 다친 아군을 회복시킵니다.
  - 마법사 = **딜러** — 기본 공격력이 가장 높아 순수 화력을 담당합니다.
  - 궁수 = **서포터** — "집중 사격 지원"으로 일정 시간 파티 전체의 공격력을 올립니다.
  - 도적 = **디버퍼** — "급소 가격"으로 일정 시간 몬스터의 공격력을 30% 낮춥니다.
  - 음유시인 = **광역 힐러** — "회복의 노래"로 파티 전원의 체력을 동시에 회복시킵니다
    (성직자의 치유는 가장 다친 한 명을 집중 회복, 음유시인은 전원을 소량씩 회복).

- **파티 시스템**: 같은 방(계정 불필요, 게스트도 가능) 안에서 파티장/초대/수락
  구조로 파티를 맺을 수 있습니다. 오버월드에 상시 떠 있는 파티 HUD에서 파티원의
  체력/레벨을 실시간으로 확인하고, 파티 전용 채팅으로 대화할 수 있습니다.
  파티장이 나가면 다음 파티원에게 자동으로 위임되고, 마지막 인원이 나가면
  파티가 해체됩니다. (같은 몬스터를 공격하는 협동 전투 자체는 파티 소속과
  무관하게, 위치가 겹치는 사람끼리 그대로 진행됩니다.)
- **계정 시스템**: 아이디/비밀번호로 회원가입·로그인하면 캐릭터의 레벨·경험치·
  장비·체력이 서버(`server/data.json`)에 저장되어, 다른 기기에서 같은 서버
  주소로 로그인해도 이어서 플레이할 수 있습니다. 비밀번호는 `scrypt`로
  해시되어 저장되며, 게스트 플레이(계정 없이 "게스트로 시작하기")는 이전과
  동일하게 동작합니다.
- **길드 시스템**: 로그인한 계정으로 길드를 만들거나 기존 길드 목록에서 가입할
  수 있습니다. 길드원 목록(직업/레벨 표시), 길드장만 수정 가능한 공지사항,
  그리고 접속 여부와 무관하게 주고받을 수 있는 길드 채팅(짧은 주기로 서버를
  조회하는 폴링 방식)을 제공합니다. 길드장이 탈퇴하면 다음 길드원에게 자동
  위임되고, 마지막 인원이 나가면 길드가 자동 해체됩니다.

다음 단계(기획서 기준): 더 다양한 퀘스트/지역, 추가 던전 확장 예정입니다.

## 실행 방법 — 게임 클라이언트

### 이 샌드박스에서 확인한 방법 (네트워크 제한 환경)

작업 환경에 `npm install` 네트워크 접근이 차단되어 있어, 이미 설치되어 있던
React / TypeScript / esbuild / ws를 그대로 사용했습니다. 빌드·타입체크·
브라우저 렌더링·실제 플레이(캐릭터 생성 → 오버월드 이동 → 전투 → 성장/장비 →
두 브라우저로 멀티플레이 동기화)까지 전부 확인했습니다.

```bash
npm run build      # scripts/build.mjs 로 dist/ 에 번들 생성
npm run typecheck  # tsc --noEmit
npm run serve      # python3 -m http.server 8080 --directory dist
# 이후 브라우저에서 http://localhost:8080 접속
```

### 실제 개발 PC에서 (네트워크 있음)

```bash
npm install
npm run build
npm run serve
```

`npm install`이 정상적으로 `@types/react`, `@types/react-dom`을 받아오면
`src/types/react-shims.d.ts` 파일은 더 이상 필요 없으니 삭제하세요
(남겨두면 타입 중복 선언 오류가 날 수 있습니다).

## 실행 방법 — 멀티플레이 서버

### 로컬에서 테스트

```bash
cd server
npm install
npm start   # ws://localhost:8787 로 대기
```

게임 클라이언트의 "친구와 함께 플레이" 체크박스를 켜고 서버 주소에
`ws://localhost:8787`, 방 코드에 아무 4자리를 입력하면 같은 컴퓨터/네트워크의
다른 브라우저 탭에서도 접속해 같은 방으로 들어올 수 있습니다.

### 클라우드 배포 (친구들이 다른 네트워크에서도 접속하게 하려면)

**Render.com 예시** (`server/render.yaml` 포함):

1. 이 프로젝트를 GitHub 저장소에 올립니다.
2. Render 대시보드 → New → Web Service → 해당 저장소 선택.
3. **Root Directory를 `server`로 지정** (중요: 레포 루트가 아니라 서버 폴더).
4. Build Command: `npm install`, Start Command: `npm start` (render.yaml이
   있으면 자동 인식).
5. 배포가 끝나면 `https://oath-of-aether-server-xxxx.onrender.com` 같은
   주소가 나오는데, 게임 클라이언트에는 `wss://` 로 바꿔서 입력합니다
   (`wss://oath-of-aether-server-xxxx.onrender.com`).

Railway도 같은 방식(Root Directory만 `server`로 지정)으로 배포할 수 있습니다.

무료 플랜은 일정 시간 요청이 없으면 서버가 잠드는 경우가 많아, 친구가 접속하기
전에 서버 주소를 한 번 브라우저로 열어 깨워두면 좋습니다.

### 지금 서버가 하는 일 / 하지 않는 일

- 하는 일: 방 코드 기반 입장(없으면 자동 생성, 계정 불필요), 오버월드에서
  서로의 위치·방향·이동 상태를 실시간 중계, **같은 몬스터를 함께 공격하는
  협동 전투**(몬스터 체력 공유, 공격 대상 판정, 파티 버프/도발/회복 처리,
  처치 시 몬스터를 방 전체 지도에서 제거), **파티**(초대/수락/채팅, 방 단위),
  그리고 **계정/길드**(회원가입/로그인/캐릭터 저장, 길드 생성/가입/채팅/공지)를
  REST API(`/register`, `/login`, `/character/save`, `/guild/*`)로 제공합니다.
  최대 6인/방.
- 아직 하지 않는 일: 던전/스테이지 진행 공유, 퀘스트 진행의 서버 측 저장
  (지금은 각 클라이언트가 자신의 퀘스트 진행을 추적합니다). 던전 단계에서
  이어서 구현할 부분입니다.

### ⚠️ 배포 시 계정/길드 데이터 저장소에 대한 주의사항

계정·길드 데이터는 지금 서버 폴더 안의 **`server/data.json` 파일**에
저장됩니다(별도 DB를 설치할 수 없는 환경이라 선택한 단순한 방식입니다).
이 방식은 로컬 테스트나 항상 켜져 있는 서버(VM, 직접 운영하는 서버 등)에서는
문제없이 동작하지만, Render/Railway의 **무료 플랜처럼 파일 시스템이
일시적(ephemeral)인 호스팅**에서는 서버가 재시작되거나 재배포될 때마다
`data.json`이 초기화되어 **모든 계정/캐릭터/길드 정보가 사라집니다.**

실제 서비스로 운영하려면 다음 중 하나가 필요합니다:

1. **Render의 유료 Persistent Disk** 기능을 켜고 `server/data.json`이 그 디스크
   경로를 가리키도록 설정 (가장 간단하지만 유료).
2. Railway의 Volume 기능으로 동일하게 디스크를 마운트.
3. 장기적으로는 `server/db.js`의 `getDB()`/`persist()` 부분을 실제 DB
   (PostgreSQL, SQLite, Redis 등)로 교체. 다른 코드는 이 두 함수의 인터페이스만
   사용하므로 교체 범위가 비교적 좁습니다.

무료 플랜으로 "친구들과 잠깐 같이 해보는" 용도라면 지금 방식 그대로도 충분하지만,
플레이어들에게 "서버가 재배포되면 계정이 초기화될 수 있다"는 점을 미리 안내하는
것을 권장합니다.

### 클라이언트(게임 화면) 배포

`server/`는 WebSocket + REST API 서버만 담당하고, 실제로 플레이어가 보는
웹 페이지(`dist/` 폴더)는 별도의 정적 호스팅에 올려야 합니다. 예:

- **Netlify / Vercel / Cloudflare Pages**: 저장소를 연결하고 빌드 명령
  `npm run build`, 배포 디렉터리 `dist`로 지정하면 됩니다.
- **GitHub Pages**: `npm run build` 후 `dist/` 내용을 `gh-pages` 브랜치에 올립니다.

클라이언트와 서버가 서로 다른 도메인에 있어도 서버 쪽에서 이미
`access-control-allow-origin: *` 로 CORS를 허용해두었기 때문에 추가 설정 없이
바로 연결됩니다. 플레이어는 게임 화면에서 "서버 주소"란에 배포된 서버의
`wss://...` 주소만 입력하면 됩니다.

## 디렉토리 구조

```
src/
  types.ts                   # 공용 타입 정의
  data/jobs.ts               # 직업별 스탯·스킬(타자 입력 문구/협동 역할 효과) 데이터
  data/monsters.ts           # 몬스터·공격 패턴(회피 문구)·경험치·드랍 데이터
  data/equipment.ts          # 장비 아이템 정의
  data/quests.ts             # 퀘스트 체인 정의
  data/overworld.ts          # 오버월드 맵 크기, 몬스터 스폰 위치, 던전 입구, 장식
  combat/engine.ts           # 문구 비교, 스킬 효과(피해/회복/버프/도발) 계산
  combat/useCombat.ts        # 솔로 전투 상태 관리 훅
  combat/useCoopCombat.ts    # 협동 전투 상태 관리 훅 (서버가 authoritative)
  combat/growth.ts           # 경험치/레벨업/장비 장착 로직
  render/sprites.ts           # 캔버스에 도트 캐릭터/몬스터를 그리는 함수
  render/SpriteCanvas.tsx     # 위 함수를 감싼 React 캔버스 컴포넌트(애니메이션)
  multiplayer/useMultiplayer.ts  # 멀티플레이 서버 연결 훅 (위치 + 협동 전투 + 파티)
  multiplayer/accountApi.ts  # 계정/길드 REST API 클라이언트
  screens/                   # 타이틀 / 로그인·회원가입 / 캐릭터 생성 / 오버월드
                              # (파티 HUD 포함) / 전투(솔로·협동) / 길드 패널 화면
  App.tsx, main.tsx
scripts/build.mjs             # esbuild 기반 빌드 스크립트
public/                       # index.html, style.css
server/                       # 멀티플레이 WebSocket + 계정/길드 REST 서버 (별도 배포 대상)
  index.js        # WebSocket(위치/협동전투/파티) + HTTP REST(계정/길드) 서버
  db.js           # 파일 기반(server/data.json) 영속 저장 (배포 시 주의사항 참고)
  auth.js         # 비밀번호 해시(scrypt)/토큰 발급
  monsterData.js, package.json, render.yaml
```
